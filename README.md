# 校园网认证 + 单线多拨 完全指南（零基础版）

> ⚠️ 仅供学习研究，请遵守所在校园网的使用规范。

---

## 一、这是什么？（说人话）

**一句话**：让你的路由器「一根网线同时拨多个号」，把校园网带宽叠加起来，而且**掉线了自动重新登录**，不用每天手动点认证。

举个栗子 🌰：

- 你宿舍只有**一根网线**，校园网认证后，单账号下载速度比如 **40 Mbps**
- 用这个方案，路由器把这根线「分身」成 2 个（甚至 4 个）虚拟接口，各自认证
- 结果下载速度 **翻倍到 80 Mbps**（因为每个虚拟接口都有独立的带宽配额）

## 二、你需要准备什么

| 东西 | 说明 |
|------|------|
| **路由器** | 一台刷了 OpenWrt / iStoreOS 的路由器 |
| **校园网账号** | 1 个（双拨）/ 2 个（四拨），每个账号限 2 台设备 |
| **电脑** | 用来远程登录路由器（Windows 自带，无需装软件） |
| **网线** | 校园网口到路由器的 WAN 口 |

> 不确定路由器是不是 OpenWrt？看登录后台地址是不是 `192.168.1.1` 且界面有「系统」「网络」「服务」这种菜单，大概率是。

## 三、核心概念（小白必看，1 分钟看懂）

### 1. 什么是「拨号」

校园网插上网线后，路由器的 WAN 口会通过 DHCP 自动拿到一个 IP（比如 `10.0.0.1`）。这个「拿到 IP 的过程」就是一次拨号。

### 2. 什么是「单线多拨」

正常情况下，**一根网线 = 一个 IP = 一次拨号**。但通过一个叫 **macvlan** 的技术，可以让路由器在**同一根物理网线**上创建多个「虚拟网卡」，每个虚拟网卡有自己独立的 MAC 地址和 IP，等于「一根线拨了多个号」。

```
物理网线 eth0
 ├─ eth0mac0（虚拟网卡 1）→ IP 10.0.0.1
 ├─ eth0mac1（虚拟网卡 2）→ IP 10.0.0.2
 ├─ eth0mac2（虚拟网卡 3）→ IP 10.0.0.x（四拨）
 └─ eth0mac3（虚拟网卡 4）→ IP 10.0.0.x（四拨）
```

### 3. 什么是「认证」

校园网不是插上就能上网，需要先「登录认证」（输入学号密码）。认证系统（这里叫 raasportal）会记录「哪个 IP/MAC 已经认证」，认证了才放行上网。

### 4. 什么是 mwan3

mwan3 是 OpenWrt 上的「多 WAN 负载均衡」插件。它的作用：把上网流量**自动分配到多个拨号**上，让下载速度叠加。没有它，你拨了 2 个号也只用得上 1 个。

### 5. 什么是 keep 保活

认证不是永久的，可能掉线（会话超时、被踢）。keep 是一个「看门狗」脚本，**每 15 秒检查一次**：发现掉线就自动重新认证，让你一直在线。

## 四、分步教程（手把手）

### 第 0 步：确认你的信息

动手前，先记下这几个东西（后面要用）：

1. **路由器登录地址**（一般是 `192.168.1.1`）
2. **路由器用户名/密码**（一般是 `root` / 你的密码）
3. **校园网账号密码**
4. **认证服务器地址**（脚本里是 `YOUR_AUTH_SERVER` 占位符，需改成你校园网的实际地址，从认证页面抓）

### 第 1 步：登录路由器

Windows 电脑按 `Win + R`，输入 `cmd` 回车，然后：

```sh
ssh root@192.168.1.1
```

> 提示输入密码时输入路由器密码（输入时屏幕不显示，正常现象）。

登录成功后会看到类似 `root@iStoreOS:~#` 的提示符，说明你已经在路由器里了。

### 第 2 步：创建虚拟接口（macvlan）

两种方式任选一种，效果一样：

#### 方式 A：命令行（最快）

先看物理 WAN 口叫什么：

```sh
ip link show | grep eth
```

找到连校园网的口（通常是 `eth0` 或 `eth1`），假设是 `eth0`，创建 2 个虚拟网卡（双拨）：

```sh
ip link add link eth0 eth0mac0 type macvlan mode vepa
ip link add link eth0 eth0mac1 type macvlan mode vepa
```

> 四拨就再加 2 个：`eth0mac2`、`eth0mac3`。

#### 方式 B：luci 网页（保姆级，点鼠标）

1. 浏览器打开 `192.168.1.1` 登录
2. 左侧菜单「**网络**」→「**设备**」（英文 Network → Devices）
3. 点「**添加设备配置**」按钮（Add device configuration）
4. 填表单：
   - **设备类型**（Device type）下拉选「**MAC VLAN**」
   - **模式**（Mode）：选「**VEPA**」（重要，多拨认证需要）
   - **设备名称**（Device name）：填 `eth0mac0`
   - **基设备**（Base device，父接口）：选 `eth0`（你连校园网的口）
   - **MAC 地址**：**留空**（系统自动生成随机 MAC）
5. 点「**保存**」→「**保存并应用**」
6. **重复第 3~5 步**，再创建一个 `eth0mac1`

> 注意：不同 OpenWrt / iStoreOS 版本的菜单名可能不同（有的没有「设备」菜单，有的叫别的名字）。如果网页里找不到「设备」，就用方式 A（命令行），更通用、一定可用。

### 第 2.5 步：配置逻辑接口（网关跃点 + DNS，重要）

创建完 macvlan 设备后，还要在「网络 → 接口」里为每个设备建一个逻辑接口，并设置**网关跃点**和 **DNS**（这两项不设会出问题）：

1. 点「**网络**」→「**接口**」（Interfaces）
2. 点「**添加新接口**」
3. 填表单：
   - **名称**：`vwan0`
   - **协议**：选「**DHCP 客户端**」
   - **设备**：选 `eth0mac0`
4. 点「**创建接口**」
5. 切到「**高级设置**」标签，填两项：
   - **网关跃点**（Gateway metric）：填 `10`
   - **使用自定义 DNS 服务器**：填 `223.5.5.5 114.114.114.114`（两个公共 DNS，中间用空格隔开）
6. 点「**保存**」→「**保存并应用**」
7. **重复第 2~6 步**，创建 `vwan1`（设备选 `eth0mac1`，**网关跃点填 `20`**，DNS 填一样的）

> **为什么必须设这两项**：
> - **网关跃点**：两个接口各自会产生一条「默认路由」，如果跃点相同会互相冲突。vwan0 填 `10`、vwan1 填 `20`，让它们错开。
> - **DNS 服务器**：DHCP 自动分配的 DNS 可能两个接口各拿一套、互相打架。手动统一填公共 DNS（`223.5.5.5` 阿里、`114.114.114.114` 腾讯）更稳定。

### 第 3 步：配置 mwan3（保姆级，跟着点就行）

mwan3 在**网页后台**配置，分「接口 → 成员 → 策略 → 规则」四层。浏览器打开 `192.168.1.1`，登录后点顶部 **「网络」→「负载均衡」**（英文 Network → Load Balancing）。

> 不同版本按钮名可能略有差异（「保存」/「保存并应用」、「添加」/「新增」），认准四层结构就行，每层改完记得点「保存并应用」。

#### 3.1 接口（Interfaces）：建 2 个虚拟 WAN

1. 进入负载均衡后，默认在「**接口**」页，点「**添加**」按钮
2. 填表单（**只填下面 3 项，其余全保持默认**）：
   - **接口名称**：填 `vwan0`
   - **绑定的接口**（Interface，下拉框）：选 `eth0mac0`
   - **跟踪 IP**（Track IP）：填 `www.baidu.com`
3. 点「**保存**」，再点「**保存并应用**」
4. **再重复一次**，建第二个：接口名称 `vwan1`，绑定接口选 `eth0mac1`，Track IP 填 `www.baidu.com`

#### 3.2 成员（Members）：每个接口配一个成员

1. 切到「**成员**」标签，点「**添加**」
2. 填表单：
   - **接口**（下拉框）：选 `vwan0`
   - **跃点数**（Metric）：填 `1`
   - **权重**（Weight）：填 `1`
3. 「保存」→「保存并应用」
4. **再重复一次**，建 vwan1 的成员（接口选 `vwan1`，Metric/Weight 都填 `1`）

#### 3.3 策略（Policies）：建 balanced 策略

1. 切到「**策略**」标签，点「**添加**」
2. 填表单：
   - **策略名称**：填 `balanced`
   - **使用的成员**：把刚才建的两个成员都**加进来**（点「添加」把 vwan0 和 vwan1 的成员各加一遍）
3. 「保存」→「保存并应用」

#### 3.4 规则（Rules）：让所有流量走 balanced

1. 切到「**规则**」标签
2. 通常已有一条默认规则（目标地址是 `0.0.0.0/0`），点它的「**编辑**」；如果一条都没有，就点「**添加**」
3. 填表单：
   - **目标地址**：填 `0.0.0.0/0`（表示「所有上网流量」）
   - **分配的接口/策略**：选 `balanced`
4. 「保存」→「保存并应用」

四层配完后，mwan3 就会把上网流量自动分散到 vwan0、vwan1 两个拨号上。

### 第 4 步：上传认证脚本

在你的电脑上，把 `2wan/campus_auth_openwrt.py` 上传到路由器：

```sh
scp 2wan/campus_auth_openwrt.py root@192.168.1.1:/zy/campus_auth.py
```

> 四拨就传 `4wan/` 里的同名文件。

### 第 5 步：配置脚本（改 4 个地方）

在路由器上编辑脚本：

```sh
vi /zy/campus_auth.py
```

> `vi` 操作：按 `i` 进入编辑，改完按 `Esc`，输入 `:wq` 回车保存退出。下面 4 处都在这一个文件里（第 4 处网关在另一个文件）。

#### 5.1 账号密码（INTERFACES）

把 `YOUR_USERNAME` / `YOUR_PASSWORD` 改成你的学号和密码：

```python
INTERFACES = [
    {"name": "vwan0", "iface": "eth0mac0", "user": "你的学号", "pass": "你的密码"},
    {"name": "vwan1", "iface": "eth0mac1", "user": "你的学号", "pass": "你的密码"},
]
```

#### 5.2 认证服务器地址（BASE_URL）

脚本顶部，把 `YOUR_AUTH_SERVER` 改成你校园网的认证服务器地址：

```python
BASE_URL = "http://YOUR_AUTH_SERVER/"   # 改成认证服务器的 IP 或域名
```

**怎么知道地址**：浏览器打开校园网认证页面（就是输学号密码登录的那个网页），看**地址栏**里的 IP 或域名，填进来。比如地址栏是 `http://10.0.0.1/`，就填 `10.0.0.1`。

#### 5.3 AES 密钥（AES_KEY）

脚本顶部：

```python
AES_KEY = b"5a3b9f207411a8ed"   # 认证系统的加密密钥
```

- **学校用 raasportal 系统**（和本项目一样）：密钥已填好，**不用改**
- **学校用别的系统**：密钥不同，需要自己从认证系统前端 JS 反解（见第八节「进阶」）

#### 5.4 网关地址（GW，在 99-campus-auth 脚本里）

只有部署静态路由（`99-campus-auth`，插手机热点才需要）时才要改：

```sh
vi /etc/hotplug.d/iface/99-campus-auth
# 找到这一行
GW="YOUR_GATEWAY"   # 改成你校园网的网关
```

**怎么知道网关**：路由器上执行 `ip route show`，看 `default via` 后面的 IP，那就是网关（比如 `default via 10.0.0.254` 里的 `10.0.0.254`）。

### 第 6 步：部署保活服务

```sh
# 上传 init.d 脚本
scp 2wan/campus_auth.initd root@192.168.1.1:/etc/init.d/campus_auth

# 赋予执行权限
chmod +x /etc/init.d/campus_auth

# 设置开机自启
/etc/init.d/campus_auth enable

# 立即启动
/etc/init.d/campus_auth start
```

### 第 7 步：安装依赖 + 测试

```sh
# 装 curl（脚本依赖它绑定接口）
opkg update && opkg install curl

# 手动认证一次，看两个接口是否都成功
python3 /zy/campus_auth.py
```

**预期输出**：

```
[vwan0] 成功 - 认证成功！
[vwan1] 成功 - 认证成功！
```

两个都「成功」，说明双拨认证搞定！现在测速，下载应该翻倍了。

## 五、日常使用

部署完成后**完全不用管**：

- 掉线了 → keep 15 秒内自动重连
- 重启路由器 → 服务自动启动
- 查看日志：`cat /tmp/campus_auth.log`

常用命令：

```sh
python3 /zy/campus_auth.py status    # 查看认证状态
python3 /zy/campus_auth.py logoff    # 手动下线
python3 /zy/campus_auth.py verify    # 验证认证+连通性
```

## 六、常见问题（FAQ）

### Q1：认证返回「失败 - 重试3次仍失败」？

说明认证服务器连不上。检查：
1. 认证服务器地址（`BASE_URL`）对不对
2. 校园网口是不是物理断开了

### Q2：下载叠加了，上传没叠加？

这是**正常现象**。校园网通常对**下行按 IP 限速**（可叠加）、对**上行按账号限速**（无法叠加）。四拨用 2 个账号才能叠加上行。

### Q3：两个接口都认证成功，但上网还是很慢？

检查 mwan3 的 balanced 策略和规则有没有配对，流量有没有真正分散到两个接口。

### Q4：重启路由器后失效了？

确认 `campus_auth.initd` 已经 `enable`（`/etc/init.d/campus_auth enabled` 应显示 enabled）。

### Q5：插了手机热点后认证服务器连不上？

这是「default 路由被抢」的问题，需要部署 `99-campus-auth` 静态路由脚本：

```sh
scp 2wan/99-campus-auth root@192.168.1.1:/etc/hotplug.d/iface/99-campus-auth
chmod +x /etc/hotplug.d/iface/99-campus-auth
ifup vwan0 && ifup vwan1
```

## 八、技术细节（进阶）

### 密码加密

认证系统的密码加密方式（从前端 `crypto.js` 逆向得到）：

- **AES-128-ECB-ZeroPadding**
- 明文 = `4 位随机 salt + 密码`
- AES 密钥已内置（系统级通用，所有账号共用同一密钥，无需修改）

### keep 检测机制

| 状态码 | 含义 | 动作 |
|--------|------|------|
| `204` | 认证在线 | 不动作 |
| `302` | 认证掉线 | 自动重连 |
| `000`/err | 网络抖动 | 跳过 |

### 静态路由

多 WAN 场景下，认证服务器（内网）可能被其他 WAN 的 default 路由抢走。`99-campus-auth` 用 `prio 50` 的 ip rule 锁死认证服务器走校园网接口。
