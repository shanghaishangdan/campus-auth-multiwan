这是什么？（说人话）

一句话：让你的路由器「一根网线同时拨多个号」，把校园网带宽叠加，而且掉线了自动切流量 + 自动重登录。

举个栗子 🌰：

  • 宿舍只有一根网线，认证后单账号下载比如 40 Mbps
  • 本方案让这根线「分身」成 2 个（甚至 4 个）虚拟接口，各自认证
  • 下载速度翻倍到 80 Mbps

本方案额外做到（相比网上普通教程）：

  • ✅ 认证掉线后，流量自动切到另一个口（不再有「一半流量走死路」）
  • ✅ DNS 永不卡（双上游并发 + 分口冗余）
  • ✅ 认证服务器静态路由自动建立（不依赖部署时机）

核心概念（1 分钟看懂）

① 拨号

校园网插线后，路由器 WAN 口通过 DHCP 自动拿到 IP（如 10.0.0.1），就是一次拨号。

② 单线多拨

通过 macvlan 技术，在同一根网线上创建多个「虚拟网卡」，每个有独立 MAC 和 IP，等于「一根线拨多个号」。

③ 认证

校园网要先登录认证（输学号密码），认证系统记录「哪个 IP/MAC 已认证」后放行上网。

④ ⚠️ 「半死」（最关键概念）

认证掉线 ≠ 网络断开。认证掉线时，接口物理状态完全正常：

项认证掉线时
DHCP 租约还在（接口有 IP）
链路还亮着（网线没断）
ping还通（ICMP 放行）
DNS还能解析（53 端口放行）
HTTP被 302 拦（唯一暴露掉线的信号）

所以 mwan3 的 ping 检测永远抓不到认证掉线（因为 ping 通）。这是后面 track_ip 要留空的根本原因。

⑤ mwan3

多 WAN 负载均衡插件，把流量自动分配到多个拨号，让下载速度叠加。

⑥ keep 保活

看门狗脚本，每 15 秒检查认证状态：发现掉线（HTTP 302）就切流量 + 重新认证。

分步教程（婴儿级，手把手）

登录路由器

Windows 按 Win + R，输入 cmd 回车：

ssh root@192.168.1.1

输密码（屏幕不显示正常），看到 root@iStoreOS:~# 成功。

创建虚拟接口（macvlan）

ip link show | grep eth
ip link add link eth0 eth0mac0 type macvlan mode vepa
ip link add link eth0 eth0mac1 type macvlan mode vepa

模式必须 VEPA。四拨再加 eth0mac2、eth0mac3。

配置逻辑接口

「网络 → 接口」→ 添加新接口：

字段vwan0vwan1
协议DHCP 客户端DHCP 客户端
设备eth0mac0eth0mac1
网关跃点1020
自定义 DNS223.5.5.5 223.6.6.6

网关跃点错开（10/20）；自定义 DNS 两个口填一样的公共 DNS。

配置 mwan3（⚠️ 有几处别照网上抄）

「网络 → 负载均衡」，分四层：

① 接口 —— track_ip 留空！initial_state 填 online！

接口名: vwan0    绑定接口: eth0mac0
Track IP: 留空（不填）
初始状态(initial_state): online

网上教程都让你填 track_ip，本方案必须留空。填了 ping 检测会把脚本切走的接口又拉回 up，切流量失效。

② 成员：vwan0 和 vwan1 各建一个（跃点 1、权重 1）。

③ 策略：建 balanced，两个成员都加进来。

④ 规则：默认规则 0.0.0.0/0 → balanced；再加一条 53 端口 → balanced（放默认规则前，做 DNS 冗余）。

配置 dnsmasq（DNS 并发）

uci set dhcp.@dnsmasq[0].allservers='1'
uci commit dhcp
/etc/init.d/dnsmasq restart

⚠️ 若 @dnsmasq[0] 不生效，先 uci show dhcp.@dnsmasq[0] 拿确切 section 名（如 cfg01411c），改用 uci set dhcp.cfg01411c.allservers='1'。

上传并配置认证脚本

scp 2wan/campus_auth_openwrt.py root@192.168.1.1:/zy/campus_auth.py
ssh root@192.168.1.1 "vi /zy/campus_auth.py"

改 BASE_URL（认证服务器地址）和 INTERFACES（学号密码）。

本脚本已内置静态路由自动建立（ensure_static_route），login 前自动执行，不需要再部署 99-campus-auth。

部署保活服务

scp 2wan/campus_auth.initd root@192.168.1.1:/etc/init.d/campus_auth
ssh root@192.168.1.1 "chmod +x /etc/init.d/campus_auth && /etc/init.d/campus_auth enable && /etc/init.d/campus_auth start"

装依赖 + 测试

opkg update && opkg install curl
python3 /zy/campus_auth.py

预期：[vwan0] 成功 - 认证成功！ 和 [vwan1] 成功。

验证自动切流量（别跳过）

# 模拟 vwan0 掉线
curl -s --interface eth0mac0 -X POST "http://10.20.33.101/api/logoff.php"
mwan3 status   # balanced 应只剩 vwan1
# 等 15 秒
python3 /zy/campus_auth.py status   # vwan0 应自动重认证
mwan3 status   # balanced 应恢复 vwan0 + vwan1

⚠️ 容易错漏的地方（必读）

坑 1：mwan3 的 track_ip 不要填

认证掉线时 ping 通，track_ip 检测判「在线」抓不到掉线，还会把脚本手动切走的接口又拉回 up。

坑 2：initial_state 必须填 online

不设 track_ip 时，填 offline 接口永远离线，流量走不了。

坑 3：认证掉线是「半死」，mwan3 检测不到

检测方式认证掉线时结果
pingICMP 放行判在线
httping302 算「有响应」判在线
nping-tcp80 端口开着判在线

唯一能测掉线的是脚本的 check_online（curl generate_204，看 204/302）。

坑 4：认证请求必须「分别走各自口」

静态路由没建立时，认证请求被 mwan3 分流到错误口（A 口源 IP 从 B 口出去），被 uRPF 丢弃，认证失败。本脚本已内置 ensure_static_route 自动建立。

坑 5：单线多拨下 metric 切换没用

两个口走同一根网线，物理断一起断，metric 主备切换是假命题。唯一冗余是「认证冗余」。

坑 6：DNS 是命门，要单独做冗余

双上游 + all-servers 并发 + mwan3 53 端口规则，三样缺一不可。

坑 7：grep "prio 50" 匹配不到

ip rule show 输出是 50: 不是 prio 50。验证用 ip rule show | grep "认证服务器IP"。

故障排查手册（踩过的坑）

Q1：认证「Failed to connect 认证服务器 port 80」

根因：静态路由没建立，认证请求被 mwan3 分流到错误口，uRPF 丢弃。

ip rule show | grep "10.20.33.101"   # 看 prio 50 规则在不在
ip route show table 100             # 看 table 100 有没有认证服务器路由

解决：用新版脚本（login 自动建），或手动触发旧版 99-campus-auth。

Q2：一个口认证不了，另一个正常

根因：静态路由没建立 + 这个口不在 mwan3 balanced。

mwan3 status          # 看 balanced 有没有这个口
mwan3 ifup 接口名     # 恢复状态

Q3：mwan3 status 显示接口「unknown」

正常，不设 track_ip 就这样，不影响参与 balanced。

Q4：balanced 只剩一个口

那个口被 mwan3 ifdown 切走了，等 keep 重认证后自动 ifup 恢复。

Q5：DNS 偶尔卡

配两个上游 + all-servers + 53 端口规则。

Q6：重启后静态路由没建立（旧版 99-campus-auth 的坑）

hotplug 只在 ifup 触发，部署晚了错过。新版脚本已把静态路由搬进 login 前自动建立，不再有此问题。

常见问题 FAQ

问题原因 / 解决
下载叠加、上传没叠加正常，上行按账号限速，四拨用 2 账号才能叠加
认证成功但网速没翻倍检查 balanced 策略和规则，看流量是否分散到两个口
重启后失效确认 campus_auth 服务已 enable
掉线后一半流量走死路半死导致，本方案靠 keep 检测 302 + ifdown 切流量解决，窗口 = keep 周期
切流量瞬间闪断正常，ifdown 重置已有连接，客户端重连走另一口

技术细节

密码加密

AES-128-ECB-ZeroPadding，明文 = 4 位随机 salt + 密码，密钥系统级通用。

keep 检测 + 切流量

状态码含义动作
204在线若之前掉线，mwan3 ifup 切回
302认证掉线mwan3 ifdown 切流量 + 重认证
err网络抖动跳过

认证请求的静态路由

prio 50 的 ip rule 锁死认证服务器走各自口，优先级远高于 mwan3（1000+），所以认证请求不被 mwan3 分流。
